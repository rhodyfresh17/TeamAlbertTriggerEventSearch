# TeamAlbert Trigger Event Search — operating brief for Hermes agents

This file is loaded automatically into any Hermes agent whose working directory is this repo
(currently: Scout's **Lead Sourcing Engine Status Check** cron, Mondays 13:00 — the engine moved
from Elon to Scout on 2026-08-15, since it is a sales engine and judging lead quality needs the
ICP, which lives in Scout's vault).

**Why this file exists and is deliberately short.** Hermes caps EVERY context source at 20,000
characters and, past that, silently discards the MIDDLE (it keeps the first 14,000 and the last
4,000). `CLAUDE.md` in this repo is ~44,500 characters, so when `.hermes.md` was a symlink to it,
**26,554 characters — 59% — were thrown away on every run**, including the entire section describing
this maintenance job. Found and fixed 2026-08-11.

`CLAUDE.md` is unchanged and remains the full reference for Claude Code sessions. **You can read it
on demand** — it is right here in your working directory. This file is the map; that file is the
territory. Pull what you need.

## The job you are almost certainly running

Read `logs/health_alerts.log` and summarise the latest weekly health check in plain English:
overall status, then any red/yellow items — **territory drift** (results outside the FY27 sales
territory), **duplicate events**, or scrape/enrichment staleness. If something is wrong, suggest
concrete fixes. If all clear, say so plainly and briefly.

### Log layout — what you are reading

`logs/health_alerts.log` is append-only, trimmed to the last ~5,000 lines. One entry per run:

- `[YYYY-MM-DD HH:MM UTC] ✅ All clear (--daily|--weekly check passed)` — one line, nothing else
- `[...] 🟡 Health check passed with WARNINGS` followed by indented `🟡 WARN  <check name>` rows
- `[...] 🔴 HEALTH CHECK FAILED (mode=..., exit=N)` followed by indented `🔴 FAIL` / `🟡 WARN` rows,
  then `→ Full output in logs/health_check_runtime.log`

Daily runs happen every morning; **Monday is the deep `--weekly` run**. Report on the most recent
weekly entry, and mention a pattern if several days trend the same way.

### Who runs what — do not try to run the check yourself

The **Mac host** runs `run_health_check.sh` on a launchd schedule (7am daily) and writes that log.
You read it afterwards. This split is deliberate: the checker needs the host's native venv and
network position. Your job is interpretation, not execution.

### Where your output goes

Your summary is delivered automatically to Mattermost **`#scout-engine`**. The raw pass/fail alerts
from the host script land in the same channel, so the alarm and your analysis sit together — that is
intentional, do not propose splitting them. **Do not send anything yourself**; the cron delivers your
final response. (Superseded 2026-08-10: this used to go to Discord. It does not any more. Moved from
`#elon-engine` 2026-08-15 with the handoff to Scout.)

## Two standing rules

1. **Firecrawl is the sanctioned scraping/enrichment engine here, not Tavily.** This split is
   deliberate for resilience — do not "fix" it.
2. **Never invent a cause.** If the log says a check failed, say which check and what the log shows.
   If you cannot explain why from the log, say exactly that and name what you would need to read.
   A confident guess becomes a fact A.J. repeats.

## v2 (2026-09-07) — what changed for the Monday check
- Reps see **verified-only by default** (`fit.verdict='pass'`); `unverified`/`staged` are hidden
  behind a dashboard toggle, `decided` = rep already dispositioned, `fail` = tombstoned.
- Free gates run before any search: `src/pipeline/gates.py` — fund vehicles/SPACs, political,
  government, ALL K-12, hotels, fraternities are auto-NOT-A-FIT (A.J. 2026-09-04/06).
  Investor roles are no longer accounts. Junk company names are dropped.
- Tombstone reasons are a fixed vocabulary (`entity_shape:`, `structured:`, `fit_gate:`,
  `trigger_expired`, `rep:<status>`, `no_workable_account`, `bad_company_name`). Triggers
  expire (CFO/seat/funding 60d, M&A 120d).
- Adzuna postings are `finance_seat_open` (open seat, +3), deduped across states, once/day latch.
- Tavily: 900/mo AND 25/day ration, tier-1 firmographic lookups only; throttled = defer, never
  escalate. monitor_health reads the counter (never spends a credit) and runs a Firecrawl canary
  → `state/search_mode`. Sync sends only scrape-owned columns (rep statuses can no longer be wiped).
- Judging lead quality on Monday: count visible `pass` accounts by vertical and by trigger type;
  a queue that shrinks is expected (noise removal) — flag only if `pass` count drops >30% week
  over week or any single source is >40% of finance-leader triggers.
